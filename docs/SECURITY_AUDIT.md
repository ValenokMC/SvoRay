# Предпубликационный аудит безопасности SvoRay 0.2.0

Дата: 1 августа 2026. Объект аудита: рабочее дерево проекта и релизные артефакты 0.2.0.
Требования взяты из раздела «Проверка безопасности перед GitHub» технического задания
0.2.0 — оно, как и рабочие заметки сессий, лежит в непубликуемом каталоге `internal`.

**Вердикт: готово к публикации.** Найденные утечки исправлены, артефакты пересобраны и
перепроверены. Оставшиеся риски перечислены в разделе 6; ни один из них не является
блокирующим для публикации, но два требуют действий владельца до и после релиза.

В этом отчёте нет значений секретов. Там, где что-то найдено, названа только категория,
файл и способ устранения.

## 3. Найдено и исправлено

### 3.1. Полное содержимое подписки попадало в `guiLogs` — исправлено

Категория: учётные данные профилей (UUID, пароли) в файле журнала на диске.

[src/ServiceLib/Handler/SubscriptionHandler.cs](../src/ServiceLib/Handler/SubscriptionHandler.cs) —
апстримный код в `ProcessDownloadResult` при неудачном разборе писал в журнал весь
скачанный текст подписки. Это список ссылок профилей, то есть учётные данные в открытом
виде, а `guiLogs` — обычный текстовый файл, который пользователи прикладывают к сообщениям
об ошибках.

Исправление: в журнал пишется только длина ответа.

Реализованной утечки не было: в журналах обоих запусков владельца (`dist\SvobodaStreet-0.1.0`
и `0.1.1`) ноль совпадений с `vless://`, `hysteria2://`, `trojan://`, `ss://` и вообще с
`http(s)://` — подписка разбиралась успешно, и ветка с записью не выполнялась.

### 3.2. Короткий ответ подписки выводился в интерфейс как есть — исправлено

Категория: возможный вывод учётных данных в поток уведомлений.

Там же: ответ короче 99 символов показывался пользователю целиком. Обычно это текстовое
сообщение сервера («срок истёк», «превышена квота») и его полезно видеть, но одиночная
ссылка профиля тоже может быть короче 99 символов.

Исправление: содержимое со схемой URI (`://`) не выводится; текстовые сообщения сервера
по-прежнему показываются.

### 3.3. Абсолютный путь с именем учётной записи Windows в публикуемых файлах — исправлено

Категория: персональные данные (имя пользователя ОС).

- `tools\FinishRename.ps1` — в комментарии и в значении параметра по умолчанию;
- `SESSION_HANDOFF_2026-08-01_RU.md` — в двух местах.

Оба файла на момент находки входили в `SvoRay-0.2.0-source.zip`, то есть путь был бы
опубликован.

Исправление: путь заменён на `%USERPROFILE%` / `$env:USERPROFILE`. При последующей чистке
проекта `FinishRename.ps1` удалён как отработавший, а журнал сессии перенесён в `internal`.
Имя учётной записи не встречается ни в одном текстовом файле исходного архива.

### 3.4. Список исключений сборщика исходников не совпадал со списком `.gitignore` — исправлено

Категория: эшелонированная защита, не реализованная утечка.

[build/Publish.ps1](../build/Publish.ps1), `Copy-CleanSourceTree` пропускала `guiConfigs`,
`guiLogs`, `guiTemps`, `binConfigs`, но не `guiBackups` и `guiFonts`, хотя в `.gitignore`
они есть. `guiBackups` — это резервные копии настроек, то есть подписки.

Исправление: список приведён в соответствие с `.gitignore`; дополнительно перед упаковкой
исходников выполняется проверка подготовленного дерева на файлы `*.db`, `*.log` и
`guiNConfig.json` в любом расположении, и сборка падает, если такой файл найден.

### 4.3. Состав релизных артефактов

`SvoRay-0.2.0-source.zip` — 460 записей. Ни одной записи в `guiConfigs`, `guiLogs`,
`guiTemps`, `guiBackups`, `binConfigs`, ни одного `.db`, `.log`, `bin/`, `obj/`, `.vs/`,
`.git/`. Имя учётной записи Windows не встречается ни в одном текстовом файле.

`SvoRay-0.2.0-win-x64.zip` — 39 записей: клиент, `AmazTool.exe`, нативные библиотеки WPF/Skia,
`bin\` с ядрами и geo-данными, четыре файла документации. Сгенерированных конфигов, баз и
журналов нет.

`SvoRay-0.2.0-setup.exe` — прямая распаковка невозможна: 7-Zip не открывает формат Inno
Setup 6.7, а `innounp` в системе отсутствует и его установка означала бы загрузку
исполняемого файла из стороннего источника. Состав проверен по построению:

1. Секция `[Files]` в [build/SvoRay.iss](../build/SvoRay.iss) — одна строка, рекурсивно
   включающая каталог publish, и никаких других источников.
2. Каталог publish перечислен пофайлово и совпадает с portable-архивом: 39 файлов,
   расхождений по составу и размерам нет.
3. Ни один файл каталога publish не новее собранного `setup.exe`, то есть в установщик
   попало ровно проверенное содержимое.
4. Побайтовое сканирование `setup.exe` на маркеры персональных данных ничего не нашло,
   но результат неинформативен: полезная нагрузка сжата LZMA2.

Прямая проверка установленного набора файлов возможна только в ходе теста установки — см. 6.3.

`SHA256SUMS.txt` пересчитан после пересборки и сверен с фактическими файлами: совпадает
для всех трёх артефактов.

### 4.4. Каталоги предыдущих версий

На момент аудита `dist\SvobodaStreet-0.1.0-win-x64` и `dist\SvobodaStreet-0.1.1-win-x64`
содержали `guiConfigs`, `binConfigs`, `guiLogs` и `guiTemps` с живыми данными владельца.
Предыдущий handoff предупреждал только про 0.1.0 — **0.1.1 запускался с реальной подпиской

Архивы `SvobodaStreet-0.1.*-win-x64.zip` и `-source.zip` при этом были чистые: 39 и 446

В релиз 0.2.0 они попасть не могли: `dist` исключён и из сборщика исходников, и из
`.gitignore`. После аудита владелец удалил оба каталога вместе со всеми файлами 0.1.x —
в проекте их больше нет.

### 4.5. Сеть и обновления

- Проверка TLS-сертификатов не отключена: соответствующий callback в
  [DownloaderHelper.cs](../src/ServiceLib/Helper/DownloaderHelper.cs) закомментирован,
  действует проверка по умолчанию, разрешены только TLS 1.2 и 1.3.
- URL подписки при HTTP-ошибке пишется в журнал только схемой и хостом (`RedactUrl`
  в [DownloadService.cs](../src/ServiceLib/Services/DownloadService.cs)) — исправление
  предыдущей сессии, подтверждено.
- Самообновление приложения недоступно: `CoreInfoManager.GetCheckUpdateCoreTypes()` не
  возвращает `ECoreType.v2rayN`, поэтому пункт не появляется в списке обновлений и
  апстримная сборка v2rayN не может заменить форк. Ограничение ТЗ выполнено.

## 5. Артефакты после пересборки

Артефакты, существовавшие до аудита, заменены: они собраны из кода с утечкой 3.1 и
публиковать их нельзя. Размеры пересобранных: 98,3 МБ, 140,3 МБ, 7,25 МБ.

Контрольные суммы — в `dist\SHA256SUMS.txt`, они пересчитаны после пересборки и сверены с
фактическими файлами. Здесь они намеренно не продублированы: этот отчёт входит в
`SvoRay-0.2.0-source.zip`, поэтому собственную сумму исходного архива он содержать не может.
Публиковать `SHA256SUMS.txt` следует рядом с релизом — без коммерческой подписи (6.4) это
единственный способ для пользователя проверить загрузку.

## 6. Оставшиеся риски

### 6.1. Учётные данные хранятся на диске в открытом виде

`%LOCALAPPDATA%\SvoRay\guiConfigs\guiNConfig.json` и база профилей содержат URL подписки и
учётные данные без шифрования, а сгенерированный конфиг ядра в `binConfigs` — тем более.
Это устройство самого v2rayN, менять его в рамках упрощённого клиента не предполагалось.
Защита — только права доступа NTFS к профилю пользователя. Клиент запускается с
повышением прав, поэтому данные оказываются в `%LOCALAPPDATA%` той учётной записи, под
которой выполнено повышение: на общем компьютере с отдельным администратором это будет не
папка того, кто пользуется клиентом.

### 6.2. Ядра поставляются без сверки с апстримными контрольными суммами

`build\Publish.ps1` копирует `xray.exe`, `sing-box.exe`, `wintun.dll` и `libcronet.dll` из
локальной установки официального v2rayN. Ни один из них, кроме `wintun.dll`, не подписан,
и сборка не сверяет их с опубликованными хешами релизов Xray и sing-box. Доверие к ним
равно доверию к машине сборки. Хеши зафиксированы в 4.6 — при следующей сборке их стоит
сверить с релизами апстрима, а в идеале добавить проверку в `Publish.ps1`.

### 6.3. Состав установщика проверен косвенно

См. 4.3. Цепочка «одна строка `[Files]` → перечисленный каталог → совпадение с
portable-архивом → отсутствие файлов новее setup.exe» надёжна, но это не то же самое, что
список файлов, извлечённых из самого `setup.exe`.

Чистая установка после аудита выполнена, но состав установленного каталога с архивом ещё не
сверялся. **Действие:** при следующем прогоне установки сравнить `C:\Program Files\SvoRay`
с `SvoRay-0.2.0-win-x64.zip` — этого достаточно, чтобы закрыть пункт окончательно.

### 6.4. Сборка не подписана коммерческим сертификатом

Windows SmartScreen покажет предупреждение «Неизвестный издатель». Это ожидаемо и уже
описано в тексте установщика и в `README_RU.md`. Отдельного риска утечки данных нет, но
пользователям сложнее отличить подлинную сборку от подделки — публикация
`SHA256SUMS.txt` рядом с релизом остаётся единственным способом проверки.

### 6.5. Каталоги 0.1.x с живыми данными — устранено

Риск был в том, что распакованные каталоги 0.1.0 и 0.1.1 с реальной подпиской лежали
внутри проекта: в релиз они попасть не могли, но ручное архивирование каталога проекта или
`git add -f` сделали бы утечку возможной. Владелец удалил их вместе со всеми остальными
файлами 0.1.x. В `dist` остались только четыре файла релиза 0.2.0.

Правило на будущее: запускать клиент для проверок только из установленной копии или из
временного каталога вне проекта.

### 6.6. Мёртвая ветка самообновления

`CheckUpdateViewModel.CheckUpdateN` умеет скачивать и устанавливать апстримный v2rayN;
недоступна она только потому, что `GetCheckUpdateCoreTypes()` не возвращает `v2rayN`.
При будущем слиянии с апстримом это легко потерять. Если ветка не нужна — удалить её
целиком надёжнее, чем полагаться на список.

## 7. Что аудит не покрывал

Аудит отвечает на вопрос «можно ли публиковать эти файлы», а не «безопасно ли работает
клиент в сети». Не проверялись и не входят в вердикт:

- живой тест подключения и утечек DNS/IP при работающем TUN;
- поведение при потере соединения (fail-open или fail-closed);
- масштабирование Windows 125 % и 150 %;
- сценарии установки, обновления поверх и удаления.

Первые два — предмет отдельной проверки, если владелец сочтёт её нужной. Последние два
остаются незакрытыми критериями приёмки 0.2.0 и не относятся к безопасности публикации.
